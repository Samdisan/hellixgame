# HELIX ECHELON — LARP Command Interface

Багатосторінковий PHP-інтерфейс, який емулює внутрішню систему станції HELIX без БД (тільки JSON). Гравці бачать особисті дані, протоколи й живий термінал, а майстри керують фазами, квестами, доступами та протоколами через адмінські інструменти.

## Ключові можливості
- **Гравецький фронт:** кабінет із таймером «Вибуття експедицій…» (оновлення кожні 3 с), стрічкою подій, кнопками до протоколів/термінала/експедицій, особовими справами (3 колонки) та сторінкою «Цілі» зі сценарними задачами й чекбоксами виконання. ID персонажа показується у шапці кабінету та в особових справах.
- **Протоколи:** публічні й персональні списки відкриваються у попапах; підтримуються засекречені/урізані версії, `allowed_players`, публічні флажки, маркери NEW/General-only та гліч-оверлеї. Окремі протоколи мають кнопки для розсилки пошкоджених копій іншим фракціям.
- **Термінали:** гравці пишуть у стрічку («Запит у систему») — записи йдуть лише в адмінський термінал. Адміни можуть відповідати/видаляти та відправляти широкомовні оголошення (без командного синтаксису). Автовідповіді керуються тригерами на адмін-сторінці. Підтримуються таргетовані гравецькі нагадування (WHO/ILARIA/медики або конкретний персонаж), які приховані від інших і автоховаються через 10 с з антидублем.
- **Контроль доступів:** трирівневе (1–3) підвищення через голосування трьох спеціалістів із лімітом 3 апґрейди/год для кожного голосувальника; адміни можуть обходити обмеження й бачать історію.
- **Досьє та цілі:** персональні файли й портрети з `personal-files.json` у кабінеті; «Цілі» беруться з `goals.json`, показують стан виконання і логуються при зміні (у тому числі через адмінку).
- **Адмін-панелі:** `admin-phases.php` — хаб таймера/фаз/квестів з оновленням 3 с, панель протоколів/статусів, переходи до голосування доступів, цілей, журналу оповіщень, діагностики, консолі та менеджера автотрігерів для гравецьких повідомлень.
- **Системи життєзабезпечення:** окрема сторінка з графіками кисню/напруги/тиску. Падіння вмикається квестом «ЗБІЙ ЖИТТЄЗАБЕЗПЕЧЕННЯ» (критичний червоно-синій UI) і завершується після ручного ремонту через адмінку.
- **Візуальні стани:** UI перемикається між фазовими стилями, жовтим попередженням (OUTBREAK) і критичним режимом життєзабезпечення з пріоритетом критичного стану.
- **Атмосфера:** гліч-попапи з атмосферними/квестовими фразами, голографічні панелі, фазові кольори (зелений/жовтий/критичний та окремий червоно-синій для життєзабезпечення) і паралельні таймерні чипи.

## Архітектура даних і API
- **Файли JSON:** `players.json`, `protocols.json`, `phases.json`, `quests.json`, `timer.json`, `terminal-messages.json`, `hints.json`, `personal-files.json`, `goals.json`, `life-support.json`, `access-codes.json`, `player-progress.json`, `access-votes.json`, `message-triggers.json`.
- **Повний перелік протоколів:** див. `PROTOCOLS_FULL.md` для послідовного списку всіх документів із метаданими та текстами з `data/protocols.json`.
- **API-ендпоїнти:** логін (`/api/login.php`), таймер (`update-timer`, `get-state`), фази (`add-phase`, `set-phase`, `set-phase-outcome`), квести (`run-quest`), протоколи (`update-protocol`, `broadcast-protocol`, `mark-protocol-opened`), доступи (`update-player`, `access-vote`), термінал (`player-terminal-message`, `push-terminal-message`, `delete-terminal-message`), діагностика (`diagnostics`), тригери автоповідомлень (`admin-message-triggers`).
- **Утиліти:** `includes/helpers.php` зчитує/пише JSON, перевіряє ролі/доступи, обробляє таймер, квести, тригери та повтори (через `executed_quests` + прапор `prevent_repeat`), де-дуплікує системні повідомлення й захищає від OOM при читанні великих JSON.

## Сторінки
**Публічні/гравецькі:** `index.php`, `login.php`, `player.php`, `protocols.php`, `protocols-player.php`, `expeditions.php`, `terminal.php` (відправлення запиту, відображення приватних нагадувань), `personal-files.php`, `goals.php` (чекбокси виконання), `access-levels.php`, `life-support.php`.

**Адмінські:** `admin-phases.php` (хаб таймера/фаз/квестів), `admin-schedule.php` (розклад фаз/квестів за таймером), `admin-timer.php`, `admin-quests.php`, `admin-protocols.php`, `admin-players.php`, `admin-terminal.php` (розсилка оголошень та лог), `admin-alerts.php`, `admin-diagnostics.php`, `admin-goals.php`, `admin-message-triggers.php`, `admin-life-support.php` (редактор показників).

## Функціональні модулі
- **Протокольні попапи:** рівні доступу, allowed_players, засекречені версії, історія відкриттів (`player-progress.json`).
- **Таймер і тригери:** глобальний таймер у `data/timer.json`; тригери за elapsed/remaining секунд запускають квести; інтервал оновлення у браузері — стартове миттєве оновлення та подальші запити раз на 3 с.
- **Квести:** дії `set_phase`, `activate_protocol`, `deactivate_protocol`, `unlock_protocol`, `set_access`, `set_timer_remaining`, `set_ui_mode`, перемикання стану життєзабезпечення, push у термінал, розсилки.
- **Фази:** `data/phases.json` підтримує паралельні фази з плановими вікнами, інтенсивністю UI та ручними результатами (наприклад, ремонт систем). Кілька фаз можуть бути активні одночасно.
- **UI-стани:** `phases.json` зберігає `ui_mode` (normal/warning) і стан життєзабезпечення. Клієнти опитують `/api/get-state.php` кожні 3 секунди і:
  - показують червоно-синій критичний режим, якщо `life_support.active = true` (усі інші фазові класи та warning режим очищуються),
  - повертаються до класу поточної фази та warning-режиму (якщо `ui_mode = warning`) після переходу `life_support.outcome = repaired` або вимкнення збою,
  - тримають звичайний стиль фази при `ui_mode = normal`.
- **Термінальний чат:** `/api/player-terminal-message.php` приймає записи гравців і додає їх лише до адмінського журналу; `/api/push-terminal-message.php` відправляє широкомовні оголошення; `/api/delete-terminal-message.php` дозволяє адмінам прибирати записи. Відображення — у `terminal.php` (з приватними нагадуваннями отримувачу) та `admin/admin-terminal.php`. Спецкоманди: `/run diagnostic ALPHA-7-ZULU` (сповіщає про збій зовнішнього зв’язку), `/run check_bio <ID>` (WHO-скрінінг із 50 тематичними відповідями й спеціальною аномалією для ID 7733).
- **Голосування доступів:** `/access-levels.php` і `/api/access-vote.php` приймають голоси трьох спеціалістів; кожен із них може натиснути кнопку підвищення лише 3 рази на годину (ліміт відстежується сервером для кожного актора).
- **Цілі гравців:** `goals.php` показує задачі з `data/goals.json` і дозволяє гравцю відмітити виконання; адміни редагують через `admin/admin-goals.php` з логуванням у термінал.
- **Діагностика й алерти:** `/admin/admin-alerts.php` агрегує журнали за протоколами/доступами/фазами/гравцями; `/admin/admin-diagnostics.php` та `/api/diagnostics.php` перевіряють биті посилання між JSON-файлами.

## Етапи гри (поточна конфігурація)
- **PH_START «Прибуття та знайомство» (0–12 хв).** Стартова зелена фаза завершується на 12-й хв (720 с). Обидві версії протоколу «ПРИБУТТЯ» доступні одразу. На 3-й хв (180 с) тригер `TT_HELIX_RESTORE_PROTOCOL` запускає квест `Q_OPEN_RESTORE_PROTOCOL`, який відкриває HELIX-ACC-RESTORE-03 і шле оголошення в термінали. На 7-й хв (420 с) таймерний тригер `TT_PHASE_BRIEFING` запускає квест `Q_START_BRIEFING`, що оголошує початок блоку знайомства в межах тієї ж фази та нагадує переглянути особові справи. Додаткові спрацьовування в цьому вікні: `TT_SYNC_ENCRYPTION` на 12-й хв (720 с, ILR-KEY-99 + завдання станції), `TT_ILARIA_SEC_GAMMA` на 16-й хв (960 с, ILARIA-SEC-GAMMA), `TT_WHO_DATA_009` на 22-й хв (1320 с, WHO-DATA-009), `TT_WHO_SEC_004Y` на 23-й хв (1380 с, WHO-SEC-004.Y), `TT_WHO_MEDICAL_SCREENING` на 25-й хв (1500 с, WHO-скрінінг через /run check_bio).
- **PH_OUTBREAK «Перші симптоми» (старт 30-ї хв, вікно до 278-ї хв).** Тригер `TT_PHASE_OUTBREAK` на 30-й хв (1800 с) запускає квест `Q_OUTBREAK_ALERT`, який перемикає фазу, вмикає жовтий режим UI (нестабільні медграфи та легкі глічі) і шле попередження в обидва термінали + попапи гравцям. На старті фази додатково спрацьовують `Q_ILARIA_FAKE_STERIL` (активує протокол для Іларії 2 рівня, очищення фальшивих схем стерилізації) та `Q_STATION_PURGE_FAKE_STERIL` (завдання станції рівня 1 на знищення підроблених протоколів). На 31-й хв (1860 с) тригер `TT_WHO_PROTOCOL_ALR_01` відкриває WHO-PROTOCOL-ALR-01 для всієї команди ВООЗ. Фаза може йти паралельно з іншими та тримає середню інтенсивність UI.
- **PH_INFECTION_SYMPTOMS «Симптоми зараження» (старт 278-ї хв).** Тригер `TT_PHASE_INFECTION_SYMPTOMS` на 278-й хв (16680 с) запускає `Q_START_INFECTION_SYMPTOMS`, який перемикає фазу й шле критичне попередження, а паралельний тригер `TT_FIND_ORIGIN_PROTOCOLS` вмикає квест `Q_FIND_ORIGIN_PROTOCOLS` з вказівкою знайти всі протоколи щодо Origin. Планове вікно триває до завершення сесії (43200 с) з підвищеною інтенсивністю та глічами.
- **Квест «Збій систем життєзабезпечення» (старт 35-ї хв).** Тригер `TT_PHASE_LIFEFAIL` на 35-й хв (2100 с) запускає `Q_START_LIFEFAIL`, який переводить інтерфейс у червоний режим, обрізає глобальний таймер до 2 годин залишку й шле попередження на обидва термінали. Режим завершується після вручну встановленого ремонту.
- **Квест «Відновити код віруса Origin» (паралельно зі збоєм, старт 35-ї хв).** Квест `Q_START_ORIGIN` спрацьовує тригером `TT_PHASE_ORIGIN` на 35-й хв (2100 с) без створення нової фази, а директива Іларії знищити зразки (`Q_ILARIA_DESTROY_SAMPLES`) спрацьовує тригером `TT_ILARIA_DESTROY_SAMPLES` на 34-й хв (2040 с) й активує протокол ILR-BIOSEC-PHASE3 із опцією розсилки.

### Точки спрацьовування квестів (деталі)

- **`Q_START_BRIEFING`**
  - **Де прописаний:** `data/quests.json`, належить до `PH_START` і запускається таймерним тригером `TT_PHASE_BRIEFING`.
  - **Коли спрацьовує:** на 420-й секунді глобального таймера, щоб у межах фази «Прибуття та знайомство» оголосити початок блоку знайомства.
  - **Що робить:** шле два повідомлення у публічний та адмінський термінали: про старт блоку знайомства до 12-ї хвилини та про необхідність переглянути особові справи.

- **`Q_ILARIA_DESTROY_SAMPLES`**
  - **Де прописаний:** `data/quests.json`, належить до `PH_OUTBREAK` і має прапор `prevent_repeat`.
  - **Коли спрацьовує:** за тригером `TT_ILARIA_DESTROY_SAMPLES` у `data/timer.json` на 2040-й секунді (34-та хв), незалежно від того, що фаза Origin Recovery йде паралельно з іншими.
  - **Що робить:** активує протокол `ILR_BIOSEC_PHASE3`, шле два повідомлення у публічний та адмін-термінали (про наказ і про опцію розсилки), а завдяки `prevent_repeat` більше не повторюється при наступних оновленнях таймера.
- **`Q_FIND_ORIGIN_PROTOCOLS`**
  - **Де прописаний:** `data/quests.json`, прив’язаний до `PH_INFECTION_SYMPTOMS` й має прапор `prevent_repeat`.
  - **Коли спрацьовує:** за тригером `TT_FIND_ORIGIN_PROTOCOLS` у `data/timer.json` одночасно з `TT_PHASE_INFECTION_SYMPTOMS` (16680-та секунда).
  - **Що робить:** надсилає попередження в обидва термінали з вимогою знайти й захистити усі протоколи, пов’язані з Origin; після першого виконання більше не повторюється.

### Як читати фазовий таймлайн
- Таймер рахує лише elapsed/remaining від глобального старту; усі тригери в секундах; фронтенд опитує стан кожні 3 с.
- Кілька фаз можуть працювати одночасно — у шапці та адмін-хабі показуються всі активні з окремими чипами зворотного відліку.
- Переходи між фазами/квестами відбуваються через тригери (`data/timer.json`) або ручні дії в адмінці; квести виконують увесь фактичний апдейт (перемикання фаз, протоколи, доступи, повідомлення) і підтримують прапор `prevent_repeat`.

### Атмосферні фрази (hints.json)
- `data/hints.json` зберігає масив рядків. Система крутить їх у гліч-попапах із випадковою вибіркою; за потреби можна замінити на об’єкти `{ text, context, weight }` — скрипти читають `text`, ігноруючи решту.
- Гравці бачать підказки у плаваючих вікнах, адміни — у шапці поряд із таймером. Додайте новий рядок у `data/hints.json`, і він з’явиться в циклі.

## Окремо про зміни дизайну та станів UI
- **Пріоритет режимів.** Послідовність така: (1) критичний збій життєзабезпечення → (2) жовтий warning → (3) базовий режим фази. Якщо life-support активний, він блокує warning-стилі, а після ремонту сторінка автоматично скидає критичні класи й повертається до warning/фази без перезавантаження.
- **Базовий режим фази.** Кожна активна фаза задає власний колір шапки/карток (зелений для старту, тони жовтого/оранжевого для попереджувальних фаз, посилені глічі та темніші відтінки для пізніх фаз). Таймерні чипи й банери наслідують цей колірний профіль.
- **Жовте попередження (OUTBREAK).** Квест `Q_OUTBREAK_ALERT` переводить інтерфейс у warning-режим: шапка та таймери стають жовтими, медичні графіки «пливуть» з легкою дрижачкою/глічем, а картки отримують попереджувальний акцент. Режим автоматично вимикається після завершення фази або ручного скидання флагу `ui_mode`. Якщо паралельно активується критичний збій, жовтий шар тимчасово приглушується й повертається лише після ремонту.
- **Критичний збій життєзабезпечення.** Квест «ЗБІЙ ЖИТТЄЗАБЕЗПЕЧЕННЯ» вмикає окремий червоно-синій шар (перекриває warning і фази): шапка стає червоною з синіми спалахами, картки отримують критичні рамки, а життєві графіки трясуться інтенсивніше. Після натискання «Відремонтовано» дизайн повертається до актуального фазового або warning-стану без перезавантаження сторінки.
- **Приватні попапи та нагадування.** Візуально легкі, з автозакриттям через ~10 секунд та watchdog-таймером; адресні (WHO/ILARIA/медики/окремий гравець) і не дублюються навіть при повторному тригері. Попереджувальні тексти мають відповідний фон (жовтий для outbreak, червоно-синій для life-support), а звичайні сервісні нагадування залишаються нейтральними.

## Перевірені проблеми й пропозиції оптимізації
- **Захист від OOM на великих JSON.** `load_json` перевіряє розмір, а якщо `filesize()` недоступний — перевіряє фактичний обсяг вмісту, відмовляючись від парсу занадто великих файлів із логом попередження.
- **Кешування JSON із обмеженням.** Є LRU на 10 записів і відмова від кешу для файлів >5 MB. Пропозиція: додати TTL або явний `clear_json_cache()` на довгих CLI-скриптах/кронах.
- **Обрізання логів терміналу.** Авто-трим до 200 останніх рядків із антидублем для глобальних/таргетованих повідомлень. Пропозиція: винести старі повідомлення в архівний файл, якщо потрібна історія, щоб не зростала пам’ять.
- **Пуллінг таймера.** Всі таймери опитуються раз на 3 сек. Пропозиція: об’єднати інші періодичні запити (наприклад, стан life-support) у той самий виклик, щоб зменшити мережеве навантаження.
- **Валідація введень у терміналі.** Для команд `/run` працюють перевірки на роль/цілі й детект дублікатів. Пропозиція: централізувати парсер і додати rate-limit на команди, якщо помітите спам.

## Які текстові матеріали потрібні
Щоб заповнити сайт фактичними матеріалами без БД, підготуйте контент для JSON-файлів і ключових сторінок:
- `index.php` — короткий опис гри, місце й дата (напр. «24 січня 2026, місце: невідомо»), кілька атмосферних слоганів.
- `data/hints.json` — 20+ атмосферних підказок/фраз станції.
- `data/players.json` — імена персонажів, фракції (станція/ВООЗ/ILARIA), ролі, статуси й рівень доступу (1–5).
- `data/protocols.json` — назви, описи, рівні доступу, фаза/активність, ознака `public` та (за потреби) `allowed_players`.
- `data/terminal-messages.json` — живі повідомлення/алерти з рівнем важливості й цільовим терміналом (`public_terminal` або адмінський).
- `data/phases.json` — назви фаз, описи, час-вікна та маркер поточної фази.
- `data/timer.json` — стартовий статус таймера та майбутні тригери подій (elapsed/remaining).
- `data/quests.json` — список квестів із прив’язаною фазою, коротким описом та діями (set_phase, протоколи, доступи, повідомлення, зміна таймера).
- `data/access-codes.json` — ігрові та адмінські коди доступу (без логінів/паролів).
- `data/player-progress.json` — відкриті протоколи по кожному `player_id` (можна стартувати з порожніх списків).
