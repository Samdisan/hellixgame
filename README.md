# HELIX ECHELON — LARP Command Interface

Багатосторінковий PHP-інтерфейс, який відтворює внутрішню систему станції HELIX без БД (тільки JSON). Гравці бачать персональні дані, протоколи й живий термінал, а майстри керують фазами, квестами, доступами та протоколами через адмінські інструменти.

## Що робить система
- **Гравецький фронт:** особистий кабінет з таймером, останніми подіями, кнопками до протоколів/термінала/експедицій, сторінка особових справ у три колонки та сторінка «Цілі» зі сценарними задачами.
- **Протоколи:** публічні та персональні списки відображаються у попапах; підтримуються редаговані доступи, приховані/засекречені версії та маркери NEW/General-only.
- **Таймер і фази:** один глобальний таймер (elapsed/remaining) з час-вікнами фаз. Авто-тригери запускають квести, що перемикають фази (PH_INTRO → PH_BRIEFING) і відкривають протоколи на визначених хвилинах.
- **Термінали:** гравецький та адмінський термінали читають одну стрічку; адмін-команди `/msg`/`/run`/`/setaccess`/`/phase` одразу логуються для обох цільових терміналів.
- **Контроль доступів:** трирівнева (1–3) система підвищення через голосування Глен Росс / Кроу / Кіра Сато з обмеженням 3 апґрейдів на годину; адміни можуть обходити обмеження.
- **Адмін-панелі:** таймер/фази з живими односекундними оновленнями, компактні протоколи, список гравців, квести, цілі гравців (admin-goals), діагностика й консоль повідомлень.

## Запуск локально
1. Встановіть PHP 8+.
2. Запустіть вбудований сервер:
   ```bash
   php -S localhost:8000
   ```
3. Відкрийте `http://localhost:8000`.

## Доступи за замовчуванням
- Гравці: `station-1492`, `who-9910`, `ilaria-7733`
- Адмін: `admin-master`

## Структура проєкту
- `/assets/css` — основні стилі (`main.css`, `admin.css`).
- `/assets/js` — фронтові скрипти (`main.js`, `player.js`, `terminal.js`, `admin-*.js`).
- `/data/*.json` — гравці, протоколи, квести, фази, таймер, коди доступу, підказки та прогрес гравців.
- `/includes/helpers.php` — завантаження/збереження JSON, перевірки доступу, утиліти.
- `/partials/` — заголовок/футер.
- `/api/` — ендпоїнти для входу, оновлення таймера, зміни фаз, гравців, протоколів, квестів і термінальних повідомлень.
- `/admin/` — адмін-сторінки (таймер, фази, протоколи, квести, гравці, термінал, діагностика).

## Публічні сторінки
- `index.php` — публічна головна з атмосферою.
- `login.php` — вхід по коду (гравець/адмін) → `/api/login.php`.
- `player.php` — панель гравця з таймером і останніми подіями.
- `protocols.php` — публічні протоколи.
- `protocols-player.php` — особисті протоколи з маркуванням NEW і записом прогресу через `/api/mark-protocol-opened.php`.
- `expeditions.php` — перелік персонажів за фракціями.
- `terminal.php` — живий термінал (polling `/api/get-terminal-messages.php`).

## Стиль та UX
Темна «біолабораторія» з легкими глічами, акценти бірюзового/пурпурового, адаптивна верстка і рандомні підказки станції.

## Фази гри (поточна конфігурація)
- **PH_INTRO — «Прибуття» (0–7 хв).** Стартова зелена фаза, легкі глічі. Плановий кінець на 420-й секунді. На 180-й секунді тригер відкриває протокол відновлення доступів HELIX-ACC-RESTORE-03; по завершенню вмикається перехід до наступної фази.
- **PH_BRIEFING — «Знайомство» (7–12 хв).** Перехідний період знайомства; одразу запускає квест Q_BRIEFING_ALERT, що шле нагадування в усі термінали переглянути особові справи. На 10-й хвилині тригер TT_WHO_SEC_004Y запускає квест Q_WHO_CORRIDOR_ALERT і відкриває протокол WHO-SEC-004.Y для агента безпеки ВООЗ. На 11-й хвилині тригер TT_WHO_DATA_009 запускає квест Q_WHO_WHITE_ZONE, який відкриває протокол WHO-DATA-009 для програміста ВООЗ і шле інструкцію до терміналів. За потреби з цієї фази можна вручну або тригером перейти в критичний режим.
- **PH_LIFEFAIL — «Збій систем життєзабезпечення» (плановий старт ~12 хв).** Критичний червоний режим: квест Q_START_LIFEFAIL переводить сайт у тривогу, обрізає глобальний таймер до 2 годин і розсилає попередження на обидва термінали. Триває до втручання майстра або завершення гри.

### Атмосферні фрази (hints.json)
- Зберігаються у `data/hints.json` як масив `{ id, text, context, weight }`.
- Використовуються у верхніх підказках/спливаючих вікнах на всіх сторінках: система бере випадкову фразу, зважену `weight`, за контекстом поточної фази (context: `any`, `intro`, `briefing`, тощо).
- Гравці бачать їх у плаваючих “glitch” вікнах; адміни — у шапці поряд із таймером.
- Щоб додати нову атмосферну фразу, просто допишіть рядок у `data/hints.json` і вона автоматично з’явиться в циклі підказок.

## Візуалізації
Детальні макети кожної сторінки тепер у `VISUALS.md` з окремими схемами для публічних і адмінських екранів.

## Які текстові матеріали потрібні
Щоб заповнити сайт фактичними матеріалами без БД, підготуйте контент для JSON-файлів і ключових сторінок:
- `index.php` — короткий опис гри, місце й дата (напр. «24 січня 2026, місце: невідомо»), кілька атмосферних слоганів.
- `data/hints.json` — 5–15 атмосферних підказок/фраз станції.
- `data/players.json` — імена персонажів, фракції (станція/ВООЗ/ILARIA), ролі, статуси й рівень доступу (1–5).
- `data/protocols.json` — назви, описи, рівні доступу, фаза/активність, ознака `public` та (за потреби) `allowed_players`.
- `data/terminal-messages.json` — живі повідомлення/алерти з рівнем важливості й цільовим терміналом (`public_terminal` або адмінський).
- `data/phases.json` — назви фаз, описи, час-вікна та маркер поточної фази.
- `data/timer.json` — стартовий статус таймера та майбутні тригери подій (elapsed/remaining).
- `data/quests.json` — список квестів із прив’язаною фазою, коротким описом та діями (set_phase, протоколи, доступи, повідомлення).
- `data/access-codes.json` — ігрові та адмінські коди доступу (без логінів/паролів).
- `data/player-progress.json` — відкриті протоколи по кожному `player_id` (можна стартувати з порожніх списків).
