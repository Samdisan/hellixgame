# HELIX ECHELON — LARP Command Interface

Багатосторінковий PHP-інтерфейс, який емулює внутрішню систему станції HELIX без БД (тільки JSON). Гравці бачать особисті дані, протоколи й живий термінал, а майстри керують фазами, квестами, доступами та протоколами через адмінські інструменти.

## Ключові можливості
- **Гравецький фронт:** кабінет з таймером «Вибуття експедицій через…», останніми подіями, кнопками до протоколів/термінала/експедицій, особові справи (3 колонки) та сторінка «Цілі» зі сценарними задачами.
- **Протоколи:** публічні й персональні списки відкриваються у попапах; підтримуються засекречені/урізані версії, allowed_players, публічні флажки, маркери NEW/General-only та гліч-оверлеї. Окремі протоколи мають кнопки для розсилки пошкоджених копій іншим фракціям.
- **Термінали:** гравці пишуть у стрічку («Заявка в систему»), адміни бачать ті ж записи, можуть відповідати/видаляти; команди `/msg` `/run` `/setaccess` `/phase` логуються в усі цілі. Автовідповіді керуються тригерами на адмін-сторінці.
- **Контроль доступів:** трирівневе (1–3) підвищення через голосування трьох спеціалістів із лімітом 3 апґрейди/год; адміни можуть обходити обмеження й бачать історію.
- **Досьє та цілі:** персональні файли й портрети з `personal-files.json` у кабінеті; «Цілі» беруться з `goals.json` і редагуються адмінами (логування у термінал).
- **Адмін-панелі:** основна сторінка `admin-phases.php` поєднує таймер/фази/квести з оновленням 1 с, показує протоколи/статуси й веде до голосування доступів, цілей (admin-goals), журналу оповіщень, діагностики, консолі та менеджера автотрігерів для гравецьких повідомлень.
- **Системи життєзабезпечення:** окрема сторінка з графіками кисню/напруги/тиску, що плавно падають у фазі PH_LIFEFAIL; підключено до фазового таймера й відтворює тривожний режим у реальному часі. Є адмін-редактор сенсорів для швидкої зміни значень.
- **Атмосфера:** гліч-попапи з атмосферними/квестовими фразами, голографічні панелі, фазові кольори (зелений/жовтий/червоний/критичний) та паралельні таймерні чипи.

## Архітектура даних і API
- **Файли JSON:** `players.json`, `protocols.json`, `phases.json`, `quests.json`, `timer.json`, `terminal-messages.json`, `hints.json`, `personal-files.json`, `goals.json`, `life-support.json`, `access-codes.json`, `player-progress.json`, `access-votes.json`, `message-triggers.json`.
- **Повний перелік протоколів:** див. `PROTOCOLS_FULL.md` для послідовного списку всіх документів із метаданими та текстами з `data/protocols.json`.
- **API-ендпоїнти:** логін (`/api/login.php`), таймер (`update-timer`, `get-state`), фази (`add-phase`, `set-phase`, `set-phase-outcome`), квести (`run-quest`), протоколи (`update-protocol`, `broadcast-protocol`, `mark-protocol-opened`), доступи (`update-player`, `access-vote`), термінал (`player-terminal-message`, `push-terminal-message`, `delete-terminal-message`, `admin-command`), діагностика (`diagnostics`), тригери автоповідомлень (`admin-message-triggers`).
- **Утиліти:** `includes/helpers.php` зчитує/пише JSON, перевіряє ролі/доступи, обробляє таймер, квести, тригери та повтори (через `executed_quests` + прапор `prevent_repeat`).

## Сторінки
**Публічні/гравецькі:** `index.php`, `login.php`, `player.php`, `protocols.php`, `protocols-player.php`, `expeditions.php`, `terminal.php`, `personal-files.php`, `goals.php`, `access-levels.php`, `life-support.php`.

**Адмінські:** `admin-phases.php` (хаб таймера/фаз/квестів), `admin-schedule.php` (розклад фаз/квестів за таймером), `admin-timer.php`, `admin-quests.php`, `admin-protocols.php`, `admin-players.php`, `admin-terminal.php`, `admin-alerts.php`, `admin-diagnostics.php`, `admin-goals.php`, `admin-message-triggers.php`, `admin-life-support.php` (редактор показників).

## Функціональні модулі
- **Протокольні попапи:** рівні доступу, allowed_players, засекречені версії, історія відкриттів (`player-progress.json`).
- **Таймер і тригери:** глобальний таймер у `data/timer.json`; тригери за elapsed/remaining секунд запускають квести; інтервал оновлення у браузері — 1 с.
- **Квести:** дії `set_phase`, `activate_protocol`, `deactivate_protocol`, `unlock_protocol`, `set_access`, `set_timer_remaining`, push у термінал, розсилки.
- **Фази:** `data/phases.json` підтримує паралельні фази з плановими вікнами, інтенсивністю UI та ручними результатами (наприклад, ремонт систем). Кілька фаз можуть бути активні одночасно.
- **Термінальний чат:** `/api/player-terminal-message.php` дає гравцям писати в стрічку; `/api/delete-terminal-message.php` дозволяє адмінам прибирати записи; відображення — у `terminal.php` та `admin/admin-terminal.php`.
- **Голосування доступів:** `/access-levels.php` і `/api/access-vote.php` приймають голоси трьох спеціалістів; API відмовляє при перевищенні ліміту 3 апґрейдів на годину.
- **Цілі гравців:** `goals.php` показує задачі з `data/goals.json`; адміни редагують через `admin/admin-goals.php` з логуванням у термінал.
- **Діагностика й алерти:** `/admin/admin-alerts.php` агрегує журнали за протоколами/доступами/фазами/гравцями; `/admin/admin-diagnostics.php` та `/api/diagnostics.php` перевіряють биті посилання між JSON-файлами.

## Етапи гри (поточна конфігурація)
- **PH_INTRO «Прибуття» (0–7 хв, планове закінчення на 420-й секунді).** Стартова зелена фаза. Обидві версії протоколу «ПРИБУТТЯ» доступні одразу. На 180-й секунді тригер `TT_HELIX_RESTORE_PROTOCOL` запускає квест `Q_OPEN_RESTORE_PROTOCOL`, який відкриває HELIX-ACC-RESTORE-03 і шле оголошення в термінали.
- **PH_BRIEFING «Знайомство» (7–12 хв, планове закінчення на 720-й секунді).** Запускається квестом `Q_START_BRIEFING` на 420-й секунді. Стартовий квест `Q_BRIEFING_ALERT` нагадує всім про перегляд особових справ. Додаткові спрацьовування: `TT_ILARIA_SEC_GAMMA` на 540-й секунді (ILARIA-SEC-GAMMA), `TT_WHO_SEC_004Y` на 600-й секунді (WHO-SEC-004.Y), `TT_WHO_DATA_009` на 660-й секунді (WHO-DATA-009).
- **PH_OUTBREAK «Перші симптоми» (старт ~20-ї хв, вікно до 15600-ї секунди).** Тригер `TT_PHASE_OUTBREAK` на 1200-й секунді запускає квест `Q_OUTBREAK_ALERT`, який активує фазу й шле попередження в обидва термінали. На старті фази додатково спрацьовують `Q_ILARIA_FAKE_STERIL` (активує протокол для Іларії 2 рівня, очищення фальшивих схем стерилізації) та `Q_STATION_PURGE_FAKE_STERIL` (завдання станції рівня 1 на знищення підроблених протоколів). Фаза може йти паралельно з іншими та тримає середню інтенсивність UI.
- **PH_LIFEFAIL «Збій систем життєзабезпечення» (старт ~13-ї хв).** Тригер `TT_PHASE_LIFEFAIL` на 780-й секунді запускає квест `Q_START_LIFEFAIL`, який перемикає сайт у червоний режим, обрізає глобальний таймер до 2 годин залишку й шле попередження на обидва термінали. Майстер фіксує результат (відремонтовано/не відремонтовано); у разі ремонту фаза припиняє фарбувати інтерфейс.
- **PH_ORIGIN_RECOVERY «Відновити код віруса Origin» (паралельно зі збоєм, старт ~13-ї хв, тривалість ~4 години).** Фаза стартує квестом `Q_START_ORIGIN` через тригер `TT_PHASE_ORIGIN` на 780-й секунді й живе паралельно з PH_LIFEFAIL. Має власний 4-годинний відлік і показується окремим чипом у таймерах. Директива Іларії знищити зразки (`Q_ILARIA_DESTROY_SAMPLES`) спрацьовує тригером `TT_ILARIA_DESTROY_SAMPLES` на 960-й секунді (16-та хв) і активує протокол ILR-BIOSEC-PHASE3 із опцією розсилки.

### Точки спрацьовування квестів (деталі)

- **`Q_BRIEFING_ALERT`**
  - **Де прописаний:** `data/quests.json`, прив’язаний до `PH_BRIEFING` у `data/phases.json` через `on_start_quests`.
  - **Коли спрацьовує:** одразу після перемикання в фазу «Знайомство» (`Q_START_BRIEFING` → `set_phase PH_BRIEFING`), тобто за тригером `TT_PHASE_BRIEFING` на 420-й секунді глобального таймера.
  - **Що робить:** шле сповіщення в обидва термінали з вимогою переглянути особові справи з урахуванням рівня доступу. Повторне відтворення блокується, бо фаза запускає його лише один раз при вході.

- **`Q_ILARIA_DESTROY_SAMPLES`**
  - **Де прописаний:** `data/quests.json`, належить до `PH_ORIGIN_RECOVERY` і має прапор `prevent_repeat`.
  - **Коли спрацьовує:** за тригером `TT_ILARIA_DESTROY_SAMPLES` у `data/timer.json` на 960-й секунді (16-та хв), незалежно від того, що фаза Origin Recovery йде паралельно з іншими.
  - **Що робить:** активує протокол `ILR_BIOSEC_PHASE3`, шле два повідомлення у публічний та адмін-термінали (про наказ і про опцію розсилки), а завдяки `prevent_repeat` більше не повторюється при наступних оновленнях таймера.

### Як читати фазовий таймлайн
- Таймер рахує лише elapsed/remaining від глобального старту; усі тригери в секундах.
- Кілька фаз можуть працювати одночасно — у шапці та адмін-хабі показуються всі активні з окремими чипами зворотного відліку.
- Переходи між фазами/квестами відбуваються через тригери (`data/timer.json`) або ручні дії в адмінці; квести виконують увесь фактичний апдейт (перемикання фаз, протоколи, доступи, повідомлення) і підтримують прапор `prevent_repeat`.

### Атмосферні фрази (hints.json)
- `data/hints.json` зберігає масив рядків. Система крутить їх у гліч-попапах із випадковою вибіркою; за потреби можна замінити на об’єкти `{ text, context, weight }` — скрипти читають `text`, ігноруючи решту.
- Гравці бачать підказки у плаваючих вікнах, адміни — у шапці поряд із таймером. Додайте новий рядок у `data/hints.json`, і він з’явиться в циклі.

## Запуск локально
1. Встановіть PHP 8+.
2. Запустіть вбудований сервер:
   ```bash
   php -S localhost:8000
   ```
3. Відкрийте `http://localhost:8000`.

## Доступи за замовчуванням
- Гравці: `station-1492`, `who-9910`, `ilaria-7733`
- Адмін: `admin-master`

## Структура проєкту
- `/assets/css` — основні стилі (`main.css`, `admin.css`).
- `/assets/js` — фронтові скрипти (`main.js`, `player.js`, `terminal.js`, `admin-*.js`).
- `/data/*.json` — гравці, протоколи, квести, фази, таймер, коди доступу, підказки та прогрес гравців.
- `/includes/helpers.php` — завантаження/збереження JSON, перевірки доступу, утиліти.
- `/partials/` — заголовок/футер.
- `/api/` — ендпоїнти для входу, оновлення таймера, зміни фаз, гравців, протоколів, квестів і термінальних повідомлень.
- `/admin/` — адмін-сторінки (таймер, фази, протоколи, квести, гравці, термінал, діагностика).

## Які текстові матеріали потрібні
Щоб заповнити сайт фактичними матеріалами без БД, підготуйте контент для JSON-файлів і ключових сторінок:
- `index.php` — короткий опис гри, місце й дата (напр. «24 січня 2026, місце: невідомо»), кілька атмосферних слоганів.
- `data/hints.json` — 20+ атмосферних підказок/фраз станції.
- `data/players.json` — імена персонажів, фракції (станція/ВООЗ/ILARIA), ролі, статуси й рівень доступу (1–5).
- `data/protocols.json` — назви, описи, рівні доступу, фаза/активність, ознака `public` та (за потреби) `allowed_players`.
- `data/terminal-messages.json` — живі повідомлення/алерти з рівнем важливості й цільовим терміналом (`public_terminal` або адмінський).
- `data/phases.json` — назви фаз, описи, час-вікна та маркер поточної фази.
- `data/timer.json` — стартовий статус таймера та майбутні тригери подій (elapsed/remaining).
- `data/quests.json` — список квестів із прив’язаною фазою, коротким описом та діями (set_phase, протоколи, доступи, повідомлення, зміна таймера).
- `data/access-codes.json` — ігрові та адмінські коди доступу (без логінів/паролів).
- `data/player-progress.json` — відкриті протоколи по кожному `player_id` (можна стартувати з порожніх списків).
